# 计算模型与基准拼接说明

本文件是系统的计算口径说明书，代码（`backend/src/calc/`）按此实现。

## 1. 数据约定

- 测点深度自孔口向下递增：0, s, 2s, …，间距 `s` 通常为 0.5 m，行数
  `N = 孔深 / s`。上传时行数不符、深度不等间距、同深度重复、非有限数一律拒收。
- 第 j 行（深度 d_j）读数代表**测段 j** 的倾斜：该测段顶端在 d_j、底端在 d_{j+1}，
  最底一行对应贴底测段（底端即孔底固定点 d_N）。
- 每个方向（正测 a、反测 b）各自登记所用探头编号；探头系数按生效时间取版本。

## 2. 单测段倾斜与校核和

设第 j 行正反测读数为 a_j、b_j，对应探头在测量日期生效的标定系数为 f_a、f_b：

```
原始倾斜（按弧长≈弦长直接作为正弦值）
  tilt_j = (a_j·f_a − b_j·f_b) / 2

校核和
  sum_j  = a_j·f_a + b_j·f_b
```

正反测在导管中顶轮方向相反，理想情况下 a·f_a 与 b·f_b 大小相等、符号相反：
倾斜取差值（零偏相消），校核和理论上逐深度近似常数。

**校核和可疑点**：对同一次测量全部深度的校核和取中位数 m，残差 r_j = sum_j − m；
当 |r_j| > 孔配置的容差时标为可疑，只标记、不剔除，该行照常参与位移计算。
选用中位数而非均值，是为了让个别坏点不污染参考基准。

## 3. 累计位移（单基准段内）

孔底为位移零点，自孔底向上逐段累加（L = 测段长度，单位换成 mm）：

```
D_N = 0
D_j = D_{j+1} + tilt_j · L          （原始累计）
```

相对位移剖面要扣掉该基准段**首测**（anchor）的原始累计，消除导管初弯曲：

```
disp_j(t) = L · Σ_{r ≥ j} [ tilt_r(t) − tilt_r(anchor) ]
```

### 小算例验证

L = 0.5 m = 500 mm，从孔底向上三个测段相对初始测量的倾斜正弦为
0、0.004、0.002（即底测段无变化、中间段 0.004、顶测段 0.002）：

- 底测段顶端：0
- 中间段顶端：0 + 0.004 × 500 = **2 mm**
- 顶测段（孔口）：2 + 0.002 × 500 = **3 mm**

由 `backend/test/profile.test.ts` 的「三测段算例」锁定。

## 4. 速率与预警分级

两次相邻测量（按 measured_at、同日按 created_at 排序）之间：

```
rate_j = (disp_j(本次) − disp_j(上一次)) / Δt(天)
```

- 首次测量、以及与上一次同日（Δt = 0）时速率记为 null，不参与定级；
- 同一深度取速率绝对值对照该孔蓝/黄/红阈值（严格递增，否则拒收）；
- 整测等级 = 全部深度等级中的最高者。
- 总览页「当前等级」= 该孔最新一次测量的整测等级。

## 5. 基准切换与拼接（本系统的选型）

下列事件产生新基准段（`datum_segments`，段内含若干测量）：

- `initial`：首测建立初始基准；
- `probe_change`：更换探头（题目里前后两段曲线接不上的主因）；
- `repair`：测斜管受损修复；
- `reset`：正式重设初始测量。

新段首测在新坐标系中重新置零。新段之后的位移如何与旧段接起来，有两个候选：

**方案一（直接叠加）**：把旧段最后一次测量的整条累计剖面作为新段起点。
问题：换探头通常带一个近似常数的角度零偏 δ，新探头首测在每个深度都读得出 δ，
直接叠加会把这 δ·L 沿孔深累加，在拼接处制造一个孔口最大、孔底为零的楔形刚体台阶，
被误判成真变形。

**方案二（本系统选用：相邻两测中位数估系统偏移，再续接）**：

```
δ_j = tilt_j(新段首测) − tilt_j(旧段末测)        逐深度
δ   = median_j(δ_j)
```

拼接时在新段原始倾斜上扣除 δ（等价于把新探头零偏对齐到旧探头），段间台阶
只保留逐深度差值的**非常数部分**，再续接旧段末测的剖面：

```
base_k(j) = base_{k-1}(j)
          + L·Σ_{r≥j}[tilt_last(k-1) − tilt_first(k-1)]_r
          + L·Σ_{r≥j}[tilt_first(k) − tilt_last(k-1) − δ_k]_r
```

孔底固定点恒为 0。

**为什么用中位数**：换探头/修复瞬间默认地层未发生变化，两次读数之差主要是
探头零偏，且零偏对所有深度一视同仁；真正的局部变形只集中在少数深度，中位数
天然把这些少数点排除在外，比逐点平均鲁棒。

**代价（明确写出）**：

1. 若紧邻两次测量之间的变化发生在**多数深度**（整体性倾斜、整体滑移），
   中位数会把真实变形误当成零偏吸收掉，拼接后该段变形被低估；
2. 导管修复若改变了导管在多数深度处的形状，δ 本身被污染，拼接只对常数部分有效，
   非常数形状差异会表现为孔深方向的台阶——此时段原因应记 `repair`，
   由人工对照剖面图上的「基准切换」标注复核，必要时以新段为准断开历史；
3. δ 由紧邻两次测量估计，若这两次本身读数质量差（校核和大量可疑），
   估计会跟着不可靠；建议换探头后尽快做第一次测量。

前端在**剖面叠加图**上把每个基准段的首测画成虚线并打紫色「基准切换」图钉，
段列表（原因、起点时间）显示在图下方，保证拼接位置对使用者可见。

## 6. 更正、级联重算与判级留痕

任何写入——上传、补录、更正测量、登记/改期标定、改阈值、建基准段——之后，
系统都在该孔一把事务级咨询锁（`pg_advisory_xact_lock`）内执行同一个全量函数
`computeHole(该孔当前全部测量, 当前基准段, 当前标定版本, 当前配置)`，然后：

- **派生缓存**（`derived_profiles`：剖面、速率、整测等级、拼接 δ）整孔删除重写；
- **判级快照**（`assessment_snapshots`）只追加，永不更新、永不删除。

因此两条性质由构造保证，而不是靠补丁维护：

1. **增量 == 全量**：「按当前数据做一次增量更新」与「把该孔全部测量从头重算」
   调用的是同一个纯函数、同一份当前输入，结果逐位一致；
2. **补录自动重排**：测量按 (measured_at, created_at) 排序，补录到中间后，
   其前后两次测量的速率自动按新相邻关系重算。

「按当时是几级」与「按现在是几级」：

- 当时 = 该测量的**首份**快照（首次上传时计算）；更正/联动产生的每份历史快照
  也都保留，测量详情页给出完整时间线；
- 现在 = 最新一次重算的快照；
- 两者整测等级不同，或逐深度等级/速率不同时，页面并列差异表。

并发更正：测量带 `revision` 乐观锁。更正必须携带它读到的 revision，
服务端 `UPDATE … WHERE id=? AND revision=?`，两人同改只有一人成功，
另一人收到 409 冲突提示（带双方 revision），不静默覆盖；成功的更正写
`corrections` 留痕（前后 JSON）。同孔并发另有咨询锁串行化，避免重算交错。

## 7. 标定版本

`calibrations` 对同一探头保留任意多条 `(factor, effective_from)`。
测量所用系数 = effective_from ≤ measuredAt 的最新一条。

- 重新标定且只影响今后：新版本生效时间填未来，历史不变；
- 更正历史标定：新增一条生效时间在过去的版本，系统对所有用过该探头的孔
  级联重算，判级变化在测量详情的「当时/现在」里可查。
